## Introduction

### 1. Приведите формулы для Performance, Power / Dynamic Power, назовите параметры в них входящие

```math
Performance = \dfrac{1}{Time} = \dfrac{1}{N_{instrs} \cdot CPI \cdot T_{cycle}} = \dfrac{1}{N_{instrs}} \cdot IPC \cdot f,
```
$`N_{instrs}`$ - количество инструкций, 
$`IPC`$ - количество инструкций, выполняемых за один такт
$`f`$ - частота,
$`T_{cycle}`$ - время одного такта

```math
Power = Power_{dynamic} + Power_{static} = C \cdot V^2 \cdot f + leakage,
```
$`C`$ - емкость,
$`V`$ - напряжение,
$`f`$ - частота

### 2. Объясните законы Мура (Moore’s law) и Деннарда (Dennard scaling).

* Закон Мура: количество транзисторов, размещаемых на кристалле интегральной схемы, удваивается каждые 2 года

* Закон Деннарда: с каждым поколением технологий размеры транзисторов становятся меньше, но потребляемая мощность на единицу площади на кристалле остаётся одинаковой. Напряжение и ток уменьшаются при уменьшении размеров транзисторов.

### 3. Когда закончился Dennard scaling ? Чем знаменуется его окончание ?

Dennard scaling закончился около 2005 года из-за невозможности уменьшать напряжение при снижении размеров транзисторов, что вызвало перегрев. С этого момента начался переход к многоядерным процессорам и оптимизациям по энергопотреблению.

### 4. В чем заключается идея Bypassing / Data forwarding оптимизации ?

* Это оптимизация для конвейерных процессоров, позволяющая избежать задержек из-за зависимостей между инструкциями.

* Если одна инструкция зависит от результата предыдущей, вместо ожидания записи этого результата в регистр, он немедленно передаётся через специальные соединения между стадиями конвейера - инструкции могут выполняться без простоев, даже если они зависят друг от друга по данным.

### 5. Что такое Instruction-Level Parallelism ? Приведите примеры оптимизаций для его повышения

Instruction-Level Parallelism (ILP) — это способность процессора выполнять несколько инструкций одновременно, используя параллелизм на уровне отдельных инструкций.

Примеры оптимизаций:
* Суперскалярность процессора: позволяет одновременно выдавать и исполнять несколько инструкций за один такт,
достигается за счёт наличия нескольких исполнительных блоков в процессоре
* VLIW архитектура: несколько операций объединяются в одну длинную инструкцию и исполняются параллельно
* Vector CPUs: выполняют одну инструкцию сразу над всем массивом данных


## Out-of-Order

### 1. Для чего нужен Reorder Buffer (ROB) ?

Reorder Buffer (ROB) используется в Out-of-Order процессорах для хранения инструкций и их результатов, позволяя исполнять независимые инструкции вне порядка, но обеспечивая завершение инструкций в программном порядке. Также обеспечивает поддержку точек останова (precise exceptions).

### 2. В чем сложность сделать ROB размером 10000 ячеек даже в случае доступной площади и power ресурса ?

Слишком большой ROB снижает отдачу и усложняет архитектуру, несмотря на потенциальные ресурсы.

* Зависимости (WAR/WAW): при большом числе инструкций увеличивается количество ложных зависимостей, что усложняет планирование.

* Исключения: при исключении нужно сбросить весь ROB. Чем он больше, тем больше теряется выполненной работы и времени на повторную загрузку инструкций.

* Ошибки предсказаний: даже при 90% точности предсказания вероятность того, что 100-я инструкция не будет удалена — лишь ~12%. Ошибка приводит к очистке ROB и потере производительности.

* Поиски внутри ROB: требуются два поиска: при выделении (для источников) и при планировании (для готовых инструкций). ROB большого размера делает их медленными и снижает эффективность.

### 3. Как бороться с False / Anti- Dependencies по регистрам ? Что такое Register Aliases Table ?

Чтобы устранить ложные (false) и анти-зависимости, процессор может использовать больше физических регистров, чем предусмотрено архитектурой.  
Во время выполнения инструкций выполняется динамическое переименование регистров (register renaming) — архитектурные регистры остаются прежними, но каждому из них временно сопоставляется уникальный физический регистр для устранения конфликтов.

### 4. Для чего нужна Instruction Queue (IQ) (по другому Scheduler Queue (SQ) / Reservation Station) ? Когда инструкции удаляются из ROB, а когда из Scheduler Queue ?

Instruction Queue (IQ) используется для хранения инструкций, которые ещё не были исполнены.  
Её размер значительно меньше, чем у ROB, что позволяет быстрее находить готовые к выполнению инструкции — поиск осуществляется только по IQ, а не по всему ROB.

* В IQ хранятся только неисполненные инструкции.
* Инструкция удаляется из IQ сразу после исполнения.
* Из ROB она удаляется только тогда, когда завершены все предшествующие инструкции — для соблюдения порядка.


### 5. Что такое Memory Disambiguation проблема ? Как с ней бороться ?

Memory Disambiguation — это проблема корректного исполнения инструкций Load и Store в Out-of-Order процессорах, когда неизвестно заранее, обращаются ли они к одним и тем же адресам.

Store инструкции:
* Не исполняются спекулятивно (откат сложен).
* Выполняются строго в порядке программы.

Load инструкции: могут исполняться вне порядка, но только если:
* либо все предыдущие Store завершены,
* либо известно, что нет пересечения по адресам.

Методы решения:
* Store Forwarding — передача данных Store напрямую в Load.
* Буферы: Store Buffer и Load Queue.
* Разделение Store на `Store Address` и `Store Data`.
* Проверка пересечения адресов Load/Store.
* Спекулятивное выполнение Load с последующей проверкой.

### 6. Объясните смысл разделения Store инструкции на Store Address / Store Data микрооперации

* Data is not required to check that store and load have no dependency
* Address is calculated when store is executed
* But store is sent to execution only if all its sources (with data) are ready -> false dep on data

To remove false dep on data in case of absence of overlapping store instruction is executed in two steps: STA, STD
* Load is waiting for STD only if it overlaps with STA

### 7. Что такое Load speculation оптимизация ?
Разделение Store на STA и STD ускоряет выполнение, но можно пойти дальше — выполнять Load инструкции спекулятивно, не дожидаясь завершения STA. После вычисления адреса Store (STA) результат Load проверяется на корректность. Если была ошибка, выполняется откат.




## Branch Prediction

### 1. Какую информацию хранит Branch Target Buffer?

Branch Target Buffer (BTB) хранит информацию о недавно выполненных переходах.  
Для каждой инструкции перехода в BTB сохраняется:

* адрес самой инструкции (PC),
* её целевой адрес,
* тип перехода (условный или безусловный и тд).

### 3. Процессор имеет двухуровневый адаптивный предсказатель условных переходов (two-level adaptive conditional branch predictor). Предсказатель хранит направления последних переходов (branch direction) из глобальной истории (global history) в регистре истории (BHR) размером 3 бита. Pattern History Table имеет размер 8 и использует стандартные 2-битные счётчики с насыщением (2-bit saturating counters). В начальный момент времени счётчики находятся в состоянии “Strongly Not Taken”. Рассчитайте процент неверных предсказаний (missprediction rate) для данного предсказателя при выполнении следующей программы:

```cpp
for (int i = 0; i < 100; ++i)
    std::cout << i << "\n";
```

* Будет 100 заходов в цикл Taken и еще 1 выход Not Taken - 101 шаг
* 8 записей в таблице предсказаний, индексируемых значением BHR
* 2-битные счётчики, изначально во всех ячейках: Strongly Not Taken (00)
* Первые 4 итерации попадают на разные значения BHR, все предсказывают Not Taken, а реально происходит Taken -> ошибки
* После 4-й итерации BHR «устаканивается» на 111 и далее используется только одна запись PHT
* Сначала она предсказывает неверно (ещё одна ошибка), затем обучается и начинает предсказывать правильно
* В конце цикла — одно неверное предсказание на выходе, когда ожидается Not Taken, но предсказано Taken
* В итоге ошибки на итерациях: 0, 1, 2, 3, 4, 100 -> всего 6 штук -> 6/101 ~ 0,059

## Memory

### 1. В чем разница между Fully Associative, Direct Mapped и Set-Associative кэшами?

Fully Associative: 
* Любая ячейка памяти может быть размещена в любой строке кэша
* Тег сравнивается со всеми строками кэша параллельно
* Нет коллизий, но дорогая реализация и долгий поиск

Direct Mapped: 
* Каждому адресу соответствует единственная строка кэша (индекс по части адреса)
* Коллизии возможны, так как разные адреса могут отображаться в одну строку
* Простой и быстрый доступ, но подвержен thrashing

Set-Associativ: 
* Кэш делится на множества (sets), каждое множество содержит N строк
* Каждому адресу соответствует один set, внутри которого выбирается одна из N строк
* Баланс между сложностью и количеством коллизий

### 2. Для чего используется Translation Lookaside Buffer (TLB)?

TLB - кэш трансляций виртуальных адресов в физические, используемый для ускорения доступа к памяти:

* Используется MMU (Memory Management Unit) и ОС для трансляции адресов
* TLB хранит недавно использованные отображения страниц
* Обычно имеет 64–256 записей, с 2–8-way ассоциативностью
* Быстрее L1-кэша, критично для производительности

### 3. Что такое гранулярность политик замещения?

Гранулярность  определяет, как и когда принимается решение о вытеснении строки:

* Coarse-grained policies: все строки обрабатываются одинаково при вставке, различия проявляются позже
* Fine-grained policies: поведение строк различается уже при вставке, на основе дополнительных признаков

### 4. Какие есть стандартные паттерны обращения к кэшу?

Основные паттерны: 
* Recency-Friendly: частый повторный доступ к недавно использованным строкам
* Thrashing: частые коллизии, ведущие к постоянному вытеснению нужных данных
* Streaming: линейный одноразовый доступ к данным (например, чтение большого файла)
* Mixed (Scanning): чередование сканирования и повторного использования

### 5. В каком ключе LRU Insertion Policy (LIP) лучше классической LRU?

* В отличие от классической LRU, где новые блоки вставляются в MRU-позицию, LIP вставляет их в LRU-позицию
* Это снижает загрязнение кэша одноразовыми доступами
* LIP лучше справляется с Thrashing паттернами, улучшая эффективность кэша

### 6. За счёт чего BRRIP устойчива к scanning и thrashing?

* Каждой строке назначается RRPV (Re-reference Prediction Value)
* При вставке обычно присваивается RRPV = 3 (редкое переиспользование), но с небольшой вероятностью — RRPV = 2
* При попадании строка получает RRPV = 0 (наивысший приоритет)
* Scanning: одноразовые блоки быстро вытесняются
* Thrashing: полезные блоки получают приоритет и дольше остаются в кэше, а счет того что быстро вытесняются линии, к которым не было ображений

### 7. В чем основная идея политик Hawkeye и Mockingjay?

Основная идея  — использование идеальной политики Белади (Belady's MIN) как ориентира:
* Используется алгоритм  OPTgen , моделирующий работу идеальной политики на основе анализа прошлых обращений
* Hawkeye и Mockingjay обучают предсказатель, определяющий, какие строки с большей вероятностью будут использоваться повторно
* Это позволяет им более точно работать в "find_victim"

### 8. Объясните принцип работы Spatial Memory Streaming (SMS) префетчера

1. Делит адресное пространство на фиксированные  Spatial Regions .
2. Запоминает, какие строки в регионе были использованы (битовая маска).
3. При повторном доступе к региону с тем же PC префетчер воспроизводит паттерн и подгружает вероятные строки.

## Advanced Optimizations & Parallelism

### 1. Для покрытия каких сложных случаев используются Execution-based Prefetchers?

Когда в коде происходит много обращений в память, которые потенциально идут мимо кеша, из-за чего конвейер процессора будет простаивать

### 2. Что такое оптимизация Value Prediction? Для каких инструкций она, как правило, применяется в современных процессорах?

Это способ ускорить выполнение, при котором процессор заранее угадывает результат инструкции, чтобы не блокировать зависимые инструкции

Применяется чаще всего к:
* load,
* простым арифметическим операциям с предсказуемыми результатами (счётчики и тд)

Если предсказание оказалось неверным, выполняется откат и повтор

### 3. За счёт чего достигается прирост производительности при использовании Value Prediction?

За счёт устранения некоторых зависимостей по данным и за счёт наличия Value Locality

### 4. В чём разница между Value Prediction и Branch Prediction с точки зрения: – необходимости предсказания, – ожидаемого эффекта при низкой точности предсказания?

Branch Prediction предсказывает направление ветвлений и может выполняться спекулятивно почти всегда, так как цена ошибки невелика, а выигрыш значительный. 

Value Prediction, напротив, предсказывает сами значения инструкций — это сложнее, дороже при ошибке, но потенциально даёт больший прирост

### 5. Что такое оптимизация Memory Renaming?

Memory Renaming — это оптимизация, которая улучшает взаимодействие инструкций load/store с памятью за счёт отслеживания и переиспользования известных зависимостей между ними

Если найдено, что определённый store влияет на конкретный load, то значение из store можно передать напрямую в load, минуя обращение к памяти

Для реализации используется внутренняя структура (например, store/load cache и value file), которая хранит соответствие между операциями и их значениями, позволяя load получать данные напрямую от store

### 6. Объясните разницу между следующими типами многопоточности: – Fine-Grained Multithreading, – Coarse-Grained Multithreading, – Simultaneous Multithreading

| Тип многопоточности         | Принцип работы                                                                 | Когда переключается поток        | Характеристики                                                                 |
|-----------------------------|--------------------------------------------------------------------------------|----------------------------------|--------------------------------------------------------------------------------|
| Fine-Grained                | Команды от разных потоков исполняются поочерёдно в каждом такте                 | Каждый такт                      | Хорошо скрывает задержки, требует простой логики, снижает производительность одного потока |
| Coarse-Grained              | Один поток активен до крупной задержки (например, промах по кэшу), затем переключение | При большой задержке             | Прост в реализации, хуже скрывает короткие stall'ы                            |
| Simultaneous (SMT)          | Несколько потоков исполняются одновременно в одном такте                    | Потоки активны одновременно      | Максимальное использование ресурсов, высокая конкуренция, сложность реализации |

Кратко:
* Fine-Grained — быстрое чередование между потоками.
* Coarse-Grained — переключение только при паузах.
* SMT — инструкции из разных потоков выполняются параллельно.
