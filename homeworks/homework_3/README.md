## Introduction

### 1. Приведите формулы для Performance, Power / Dynamic Power, назовите параметры в них входящие

```math
Performance = \dfrac{1}{Time} = \dfrac{1}{N_{instrs} \cdot CPI \cdot T_{cycle}} = \dfrac{1}{N_{instrs}} \cdot IPC \cdot f,
```
$`N_{instrs}`$ - количество инструкций, 
$`IPC`$ - количество инструкций, выполняемых за один такт
$`f`$ - частота,
$`T_{cycle}`$ - время одного такта

```math
Power = Power_{dynamic} + Power_{static} = C \cdot V^2 \cdot f + leakage,
```
$`C`$ - емкость,
$`V`$ - напряжение,
$`f`$ - частота

### 2. Объясните законы Мура (Moore’s law) и Деннарда (Dennard scaling).

* Закон Мура: количество транзисторов, размещаемых на кристалле интегральной схемы, удваивается каждые 2 года

* Закон Деннарда: с каждым поколением технологий размеры транзисторов становятся меньше, но потребляемая мощность на единицу площади на кристалле остаётся одинаковой. Напряжение и ток уменьшаются при уменьшении размеров транзисторов.

### 3. Когда закончился Dennard scaling ? Чем знаменуется его окончание ?

Dennard scaling закончился около 2005 года из-за невозможности уменьшать напряжение при снижении размеров транзисторов, что вызвало перегрев. С этого момента начался переход к многоядерным процессорам и оптимизациям по энергопотреблению.

### 4. В чем заключается идея Bypassing / Data forwarding оптимизации ?

* Это оптимизация для конвейерных процессоров, позволяющая избежать задержек из-за зависимостей между инструкциями.

* Если одна инструкция зависит от результата предыдущей, вместо ожидания записи этого результата в регистр, он немедленно передаётся через специальные соединения между стадиями конвейера - инструкции могут выполняться без простоев, даже если они зависят друг от друга по данным.

### 5. Что такое Instruction-Level Parallelism ? Приведите примеры оптимизаций для его повышения

Instruction-Level Parallelism (ILP) — это способность процессора выполнять несколько инструкций одновременно, используя параллелизм на уровне отдельных инструкций.

Примеры оптимизаций:
* Суперскалярность процессора: позволяет одновременно выдавать и исполнять несколько инструкций за один такт,
достигается за счёт наличия нескольких исполнительных блоков в процессоре
* VLIW архитектура: несколько операций объединяются в одну длинную инструкцию и исполняются параллельно
* Vector CPUs: выполняют одну инструкцию сразу над всем массивом данных


## Out-of-Order

### 1. Для чего нужен Reorder Buffer (ROB) ?

Reorder Buffer (ROB) используется в Out-of-Order процессорах для хранения инструкций и их результатов, позволяя исполнять независимые инструкции вне порядка, но обеспечивая завершение инструкций в программном порядке. Также обеспечивает поддержку точек останова (precise exceptions).

### 2. В чем сложность сделать ROB размером 10000 ячеек даже в случае доступной площади и power ресурса ?

Слишком большой ROB снижает отдачу и усложняет архитектуру, несмотря на потенциальные ресурсы.

* Зависимости (WAR/WAW): при большом числе инструкций увеличивается количество ложных зависимостей, что усложняет планирование.

* Исключения: при исключении нужно сбросить весь ROB. Чем он больше, тем больше теряется выполненной работы и времени на повторную загрузку инструкций.

* Ошибки предсказаний: даже при 90% точности предсказания вероятность того, что 100-я инструкция не будет удалена — лишь ~12%. Ошибка приводит к очистке ROB и потере производительности.

* Поиски внутри ROB: требуются два поиска: при выделении (для источников) и при планировании (для готовых инструкций). ROB большого размера делает их медленными и снижает эффективность.

### 3. Как бороться с False / Anti- Dependencies по регистрам ? Что такое Register Aliases Table ?

Чтобы устранить ложные (false) и анти-зависимости, процессор может использовать больше физических регистров, чем предусмотрено архитектурой.  
Во время выполнения инструкций выполняется динамическое переименование регистров (register renaming) — архитектурные регистры остаются прежними, но каждому из них временно сопоставляется уникальный физический регистр для устранения конфликтов.

### 4. Для чего нужна Instruction Queue (IQ) (по другому Scheduler Queue (SQ) / Reservation Station) ? Когда инструкции удаляются из ROB, а когда из Scheduler Queue ?

Instruction Queue (IQ) используется для хранения инструкций, которые ещё не были исполнены.  
Её размер значительно меньше, чем у ROB, что позволяет быстрее находить готовые к выполнению инструкции — поиск осуществляется только по IQ, а не по всему ROB.

* В IQ хранятся только неисполненные инструкции.
* Инструкция удаляется из IQ сразу после исполнения.
* Из ROB она удаляется только тогда, когда завершены все предшествующие инструкции — для соблюдения порядка.


### 5. Что такое Memory Disambiguation проблема ? Как с ней бороться ?

Memory Disambiguation — это проблема корректного исполнения инструкций Load и Store в Out-of-Order процессорах, когда неизвестно заранее, обращаются ли они к одним и тем же адресам.

Store инструкции:
* Не исполняются спекулятивно (откат сложен).
* Выполняются строго в порядке программы.

Load инструкции: могут исполняться вне порядка, но только если:
* либо все предыдущие Store завершены,
* либо известно, что нет пересечения по адресам.

Методы решения:
* Store Forwarding — передача данных Store напрямую в Load.
* Буферы: Store Buffer и Load Queue.
* Разделение Store на `Store Address` и `Store Data`.
* Проверка пересечения адресов Load/Store.
* Спекулятивное выполнение Load с последующей проверкой.

### 7. Что такое Load speculation оптимизация ?
Разделение Store на STA и STD ускоряет выполнение, но можно пойти дальше — выполнять Load инструкции спекулятивно, не дожидаясь завершения STA. После вычисления адреса Store (STA) результат Load проверяется на корректность. Если была ошибка, выполняется откат.




## Branch Prediction

### 1. Какую информацию хранит Branch Target Buffer?

Branch Target Buffer (BTB) хранит информацию о недавно выполненных переходах.  
Для каждой инструкции перехода в BTB сохраняется:

* адрес самой инструкции (PC),
* её целевой адрес,
* тип перехода (условный или безусловный и тд).
